# Watch Supreme — инструкции для агентов

Статическая витрина магазина часов: HTML, CSS и JavaScript без сборки. Сайт: https://watch-supreme.ru. Репозиторий: https://github.com/Bravi-study/grand-watch.

## Перед работой

- Проверь `git status` и актуальность локальной ветки относительно `origin/main`; сохрани чужие изменения.
- Сверь `README.md`, `config.js` и `.github/workflows/deploy.yml` с актуальной веткой. Старые версии сайта обращались к Google прямо из браузера; действующая публикация получает каталог через GitHub Actions. Не переноси устаревшую схему в новые инструкции.
- Для добавления товара обычно нужны строка в таблице и фотографии. Код, дизайн и настройки подключения менять не требуется.

## Источник каталога

- [Google Таблица «Watch Supreme — учёт»](https://docs.google.com/spreadsheets/d/1-vAnHSq7GuFNFfnYNLmUqNNaWXAt39atc5m-usRYltY/edit), лист **«Товары»**: одна строка на часы.
- `apps-script/Code.gs` отдаёт только публичные поля. В каталог попадают строки с непустым артикулом, «На сайте» = `да` и допустимым статусом.
- При публикации GitHub Actions получает JSON из Apps Script, записывает `data/watches.json` и загружает сайт на reg.ru по FTP. Посетитель читает каталог с сайта.
- `data/watches.json` в репозитории — резервная копия. Получение каталога при публикации само по себе не обновляет этот файл в Git.
- Закупочные цены, поставщики, ссылки на GooFish, внутренние расчёты и остальные приватные колонки не должны попадать в файлы сайта или публичный JSON. Не расширяй список `PUBLIC` ради добавления позиции.

## Как добавить часы

1. Получи реальные данные и фотографии от пользователя. Не придумывай цену, год, референс, комплектность, состояние или подлинность.
2. Проверь существующие артикулы в таблице и назначь уникальный, например `W-003`. Не меняй артикулы существующих товаров: они используются в ссылках и путях фотографий.
3. Подготовь `photos/<артикул>/1.jpg`, `2.jpg` и далее. Предпочтительно квадратные фото или 4:5, около 1600 px по длинной стороне и до 400 КБ на JPEG. Первое фото — обложка. Имена файлов и регистр должны точно совпадать с путями в таблице.
4. Добавь новую строку на лист «Товары», заполнив публичные колонки:

   | Колонки | Что записывать |
   |---|---|
   | Артикул | Новый уникальный артикул |
   | Бренд, Коллекция, Модель, Референс | Данные часов; коллекция используется в фильтре |
   | Год, Диаметр, мм | Год и диаметр в миллиметрах |
   | Корпус, Механизм, Циферблат, Состояние, Описание | Подтверждённые характеристики и описание |
   | Коробка, Документы | `да` или `нет` по фактической комплектности |
   | Цена на сайте, ₽ | Цена в рублях; `0` означает «Цена по запросу», используй его только по договорённости |
   | Статус | `в наличии`, `забронировано` или `продано` |
   | На главную | `да`, если товар должен появиться на первом экране |
   | Фото | Пути через запятую или перенос строки: `photos/W-003/1.jpg, photos/W-003/2.jpg` |
   | На сайте | `да` для публикации; `нет`, пока позиция не готова |

5. Загрузи фотографии на хостинг до публикации строки. Через GitHub: папка `photos` → **Add file → Upload files** → загрузи папку артикула и сохрани изменения в `main`; затем дождись успешной выкладки. Можно загрузить фото прямо по FTP в соответствующую папку сайта.
6. После готовности фото поставь «На сайте» = `да` и запусти публикацию каталога. Не меняй заголовки колонок и не перезаписывай формулы или внутренние данные таблицы.

## Публикация

- Workflow: [.github/workflows/deploy.yml](.github/workflows/deploy.yml), **Deploy to hosting**.
- Запускается после push в `main`, по расписанию `*/15 * * * *` и вручную. Расписание может задерживаться; 15 минут — не гарантированный срок появления товара.
- Для публикации без ожидания: [GitHub Actions](https://github.com/Bravi-study/grand-watch/actions/workflows/deploy.yml) → **Run workflow** → `main`.
- Проверь шаг **Pull catalog from Google Sheet**: при ошибке таблицы workflow может успешно завершиться с резервным каталогом из репозитория. Зелёный статус сам по себе не доказывает обновление товара.
- Для обычного добавления часов не нужно заново развёртывать Apps Script или менять `SHEET_URL` и FTP-секреты. Не выводи значения секретов в отчёты.

## Проверка результата

1. Убедись, что опубликованный `https://watch-supreme.ru/data/watches.json` содержит нужный артикул, цену, статус и пути фото, а также не содержит приватных полей.
2. Открой сайт и карточку `https://watch-supreme.ru/#w/<артикул>`. Проверь видимость в каталоге, характеристики, цену, статус, обложку и остальные фотографии.
3. Проверь карточку на ширине 1440 и 390 px, фильтр коллекции и ссылки бронирования в Telegram. Проверка ссылок не требует отправки сообщений.
4. В отчёте укажи артикул, сделанные изменения, состояние публикации и что проверено. Если проверена только таблица или JSON, не называй визуальную проверку завершённой.

После продажи меняй статус на `продано`, при бронировании — на `забронировано`. Чтобы скрыть позицию полностью, поставь «На сайте» = `нет`. Эти изменения также требуют обновления каталога на хостинге.
